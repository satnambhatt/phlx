How It Works

Phalanx installs shim scripts at ~/.phalanx/bin/{npm,pip,pip3} and prepends that directory to your $PATH. Each shim invokes a small Go binary that scans, then either blocks or execs the real package manager.

1
Shell finds the shim
You type npm install lodash. Your shell searches $PATH left to right and finds ~/.phalanx/bin/npm before the real npm. Phalanx intercepts.
2
Typosquat check + version resolve
Stage 1 runs known-squat list, Levenshtein, homoglyph and separator-confusion analysers — a CRITICAL hit blocks before any download. Otherwise phalanx-npm-hook queries the npm or PyPI registry to pin ^4 → 4.17.21.
3
Trivy + behavioural in parallel
Tarball downloaded into a temp workspace. Stage 3 (Trivy CVE + licence scan) and Stage 4 (14 behavioural static-analysis rules on extracted tarball) run as goroutines. Results cached 24h in SQLite.
4
Policy gate decides
Inline policy evaluates findings. CRITICAL CVEs and unfixed HIGH CVEs block. Fixable issues warn. GPL / AGPL licences block. Optional: externalise to OPA / Rego (see docs/upgrades).
5
Real package manager runs or doesn't
If blocked: exit 1, nothing installs. If clean: Phalanx execs the real npm/pip binary with all original arguments unchanged.

Why Phalanx

Most security tools work on the wrong timeline. Phalanx acts at the exact moment of install, before anything lands.

⏱
Stops threats at the gate
Other tools scan after install. Phalanx blocks before. The vulnerable package never touches your filesystem, your lockfile, or your colleagues' machines.
👻
Invisible to developers
Clean installs show nothing. No dashboard to check, no PR comment to read, no CI job to wait for. Developers run the same commands they always have.
🔒
No account, no cloud
Runs entirely on your machine. Scan results stay in ~/.phalanx/. No telemetry, no login, no API key. The CVE database is Trivy's local cache.
🎛
Policy you own
Defaults block CRITICAL CVEs, unfixed HIGH CVEs, known typosquats, GPL / AGPL. phlx allow grants per-package exceptions. Optional upgrade to OPA / Rego for full custom rules.
🐍
npm and pip, one tool
Phalanx covers both ecosystems with the same policy, the same audit log, the same CLI. One install, two package managers protected.
🍃
Zero idle, single static binary
Hooks-only mode: 0 MB until an install triggers a scan (~150 MB peak). Written in Go — single static binary, pure-Go SQLite, no runtime needed.

Get Started

1
Install Trivy
brew install trivy on macOS · apt install trivy on Debian/Ubuntu. Optional — Phalanx fails open without it. Docker also works as fallback.
2
Pin the version
Grab the latest tag from releases — e.g. VERSION=0.1.0. Or auto-detect via the GitHub API (see terminal).
3
curl · extract · move
Single pipe downloads the archive and extracts three binaries into the working directory. Move them to /usr/local/bin — all three must live in the same directory.
4
Arm the hooks
phalanx hooks install then source ~/.zshrc. Verify with which npm — should resolve to ~/.phalanx/bin/npm.
5
Try it
Run npm install lodash. First run downloads Trivy's CVE database. Every subsequent scan is near-instant from the 24h SQLite cache.
setup
# 1 — prerequisites
$ brew install trivy

# 2 — pin latest release
$ VERSION=$(curl -s https://api.github.com/repos/\
satnambhatt/phlx/releases/latest \
| grep tag_name | cut -d'"' -f4 | sed 's/^v//')

# 3 — download · extract · install (macOS arm64)
$ curl -sSL https://github.com/satnambhatt/phlx/\
releases/download/v${VERSION}/\
phlx_${VERSION}_macos_arm64.tar.gz | tar -xz
$ sudo mv phalanx phalanx-*-hook /usr/local/bin/

# 4 — arm the shell hooks
$ phalanx hooks install
$ source ~/.zshrc
